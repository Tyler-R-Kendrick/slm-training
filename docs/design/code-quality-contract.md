# Code quality contract (module size, complexity, package principles)

This repository has 2,227 repo-owned source files and 737,447 lines. At that
size, "keep files small" is not a convention anybody can hold by reading diffs.
This document defines what is measured, what is enforced, and how the debt is
retired.

Machine enforcement: `python -m scripts.verify_code_quality` (CI, static; no
torch required). Component: `governance.code_quality` in
`src/slm_training/resources/versions.json`. Implementation:
`src/slm_training/quality/`.

---

## Why a ratchet, not a threshold

When the gate was first written the repository already violated every budget it
declares:

| Dimension | State at baseline |
| --- | --- |
| Modules over 400 lines | 531 of 2,227 (23.8%) |
| Largest module | `scripts/run_autotrain_continuous.py`, 18,665 lines (46.7x budget) |
| Complexity findings | 1,773 across 449 files |
| Components in a dependency cycle | 56 of 78 |
| Stable-dependency (SDP) violations | 80 |
| Stable-abstraction (SAP) violations | 11 |

A budget that fails 531 times on day one gets waived, and a waived budget
measures nothing. So the gate is a **ratchet**:

- Every existing violation is frozen at its current magnitude in
  `src/slm_training/resources/code_quality_baseline.json`.
- Any increase — a module growing, a new oversized file, another cycle — **fails**.
- Any decrease must be written back with `--update`, which **permanently lowers
  the ceiling**. A win cannot be spent twice.

Debt is therefore monotonically non-increasing. This is the Boy Scout rule
("always leave the campground cleaner than you found it") turned into a
build failure instead of a hope.

**Do not raise a baseline number by hand to land a change.** Split the module,
simplify the function, or break the cycle. The baseline is a record of debt
already incurred, not a budget to spend.

## What is measured

### 1. Module size — 400 physical lines

`MAX_MODULE_LINES` in `src/slm_training/quality/sources.py`. Physical lines, as
`wc -l` counts them: an objective number that needs no parser and cannot be
gamed by reformatting.

**Excluded**, because a budget levied on generated bytes measures the generator:

- `src/slm_training/web/static/**` — build output from `npm run preview:build`
  and `npm run dashboard:build` (`src/slm_training/web/static/preview/preview.js`
  alone is 98,660 minified lines).
- `node_modules/`, `dist/` — vendored and built.
- `.agents/skills/`, `.claude/skills/`, `.cursor/skills/`, `.grok/skills/`,
  `.codex/skills/` — vendored marketplace skills refreshed by `hf skills update`.
  Kept in sync with `[tool.ruff] extend-exclude` in `pyproject.toml`.
- Any file whose first five lines carry `@generated`, `Code generated by`,
  `DO NOT EDIT`, or `autogenerated by`.

The gate reads `git ls-files --cached --others --exclude-standard`, so a new
oversized module fails while it is still being written, not one commit later.

### 2. Complexity and single responsibility — ruff

Ruff already implements mccabe and the pylint function-shape rules.
Reimplementing them here would create a second, silently diverging definition of
"too complex", so ruff stays the single source of truth and the gate only
aggregates its JSON output.

| Rule | Measures | Threshold |
| --- | --- | --- |
| `C901` | cyclomatic complexity | 10 |
| `PLR0911` | return statements | 6 |
| `PLR0912` | branches | 12 |
| `PLR0913` | arguments | 8 |
| `PLR0915` | statements | 50 |

Thresholds live in `[tool.ruff.lint.mccabe]` and `[tool.ruff.lint.pylint]` in
`pyproject.toml`. They are ruff's defaults — which are also the long-standing
pylint and mccabe defaults — deliberately not tuned to whatever the codebase
happens to do today. The single exception is `max-args`, raised from 5 to 8:
this codebase uses keyword-only parameters pervasively (`def f(*, root, policy,
...)`) and ruff counts those toward the limit, so 5 penalises the safer calling
convention. 8 still flags genuine "pass a parameter object" smells.

These rules are **not** in `[tool.ruff.lint] select`, so bare `ruff check .`
stays a fast syntax-and-correctness pass. Reproduce the gate's view locally:

```
ruff check --select C901,PLR0911,PLR0912,PLR0913,PLR0915 src scripts tests
```

Findings are ratcheted **per file**, not per function, so renaming a function
does not silently discharge its debt.

### 3. Package principles — Robert C. Martin

From *Agile Software Development: Principles, Patterns, and Practices* and
*Clean Architecture*. A **component** here is a Python package directory
(`slm_training.dsl`, `slm_training.harnesses.model_build`, ...) — the smallest
unit this repository could release or reuse independently, which is the unit
Martin's principles are stated over.

Metrics, per component:

- **Ca** (afferent coupling) — components that depend on this one.
- **Ce** (efferent coupling) — components this one depends on.
- **I** (instability) = `Ce / (Ca + Ce)`. 0 = maximally stable, 1 = maximally
  unstable.
- **A** (abstractness) = abstract classes / all classes, where "abstract" means
  deriving from `ABC`/`Protocol`, using `ABCMeta`, or declaring an
  `@abstractmethod`.
- **D** (distance from the main sequence) = `|A + I - 1|`. The main sequence runs
  from (0, 1) — stable *and* abstract — to (1, 0) — unstable and concrete.

Principles enforced:

- **ADP** (Acyclic Dependencies) — the component graph must be a DAG. Cycles are
  found with Tarjan's algorithm, iteratively, so a deep graph cannot exhaust the
  recursion limit.
- **SDP** (Stable Dependencies) — depend in the direction of stability:
  `I(source) >= I(target)`. A stable component that depends on a volatile one
  inherits its volatility.
- **SAP** (Stable Abstractions) — a stable component must be abstract, or it is
  rigid: everything depends on it and nothing can vary it. Components more than
  `MAX_DISTANCE` (0.7) from the main sequence are reported as the *zone of pain*
  (stable and concrete) or the *zone of uselessness* (unstable and abstract).
  Zone-of-pain reports require at least `ZONE_OF_PAIN_MIN_DEPENDENTS` (5)
  dependents, so an ordinary concrete leaf is not noise.

Because a cycle's *membership* churns with every import while its *size* is the
thing that must fall, the ADP/SDP/SAP dimension is ratcheted as aggregate counts
rather than per-edge keys.

### 4. Component size — 20,000 lines

`MAX_COMPONENT_LINES` in `src/slm_training/quality/gate.py`. Martin's Common
Closure Principle asks that a component change for one reason; past this size
that is not credible and the component wants splitting. Three components exceed
it today, led by `slm_training.harnesses.experiments` at 103,189 lines across
181 modules.

## The findings this gate first surfaced

**`slm_training.dsl` is in the zone of pain.** Ca=46, I=0.19, A=0.04, D=0.77.
Forty-six components depend on it and it is almost entirely concrete: the most
depended-upon component in the repository is also one of the least variable.

**The dependency graph is one knot.** 54 of 78 components form a single
strongly-connected component. It is not an artefact of import-resolution: for
example `src/slm_training/dsl/harness_dsl.py:11` imports
`slm_training.data.contract`, while `src/slm_training/data/contract.py` imports
`slm_training.dsl` — a genuine two-component cycle, one of 55 such mutual pairs.

Neither is fixed by this contract; both are now measured, frozen, and unable to
get worse.

## Usage

```
python -m scripts.verify_code_quality            # gate (what CI runs)
python -m scripts.verify_code_quality --report   # full metrics, no gating
python -m scripts.verify_code_quality --update   # re-freeze the baseline
```

`--skip-complexity` drops the ruff pass for environments without ruff on PATH;
`--update` then preserves the recorded complexity ceilings rather than erasing
them.

Exit codes: `0` clean, `1` regression or unrecorded improvement, `2` the gate
could not run (no baseline, or ruff missing).

## Retiring the debt

The ratchet forbids growth; it does not by itself shrink anything. To pay debt
down, pick a target from `--report`, split it, and run `--update`. The baseline
diff in the pull request is then the receipt.

### Worked example: the first payment

`scripts/autotrain_budget.py` was carved out of
`scripts/run_autotrain_continuous.py` in the same change that introduced this
contract: eleven pure functions and five constants (including a 142-line
recorded-evidence table) that turn a policy and a deadline into the seconds,
steps and deadlines an arm may spend.

- `run_autotrain_continuous.py`: 18,665 -> 18,444 lines, and its baseline
  ceiling fell with it.
- The extracted module is 313 lines — inside budget, so it adds no new debt.
- The arithmetic gained 24 direct unit tests. It previously had none of its own:
  it could only be reached through the 13,318-line runner suite.
- All 357 existing runner tests pass unchanged; names are re-exported under
  their original private aliases so call sites and monkeypatches still resolve.

The extraction also demonstrates the package metrics catching a mistake before
it landed. The obvious home for shared harness arithmetic is
`slm_training.harness_core` — but `harness_core` importing `slm_training.levers`
would have created a new `harness_core -> slm_training -> harnesses ->
harness_core` cycle, because `levers` imports `harnesses.staged` and
`harnesses.staged` imports `harness_core`. The runner-specific budget policy
belongs to the runner, so it stayed in `scripts/`, and the ADP count did not move.

### Order of attack

Most valuable first:

1. **Break the ADP cycles.** They are what make the other two hard: a module in a
   54-component knot cannot be split without dragging the knot along.
2. **Split the largest modules.** `scripts/run_autotrain_continuous.py` (18,665
   lines, 321 top-level definitions) and `src/slm_training/models/twotower.py`
   (17,227 lines) are 46x and 43x the budget.
3. **Introduce abstractions at the stable hubs** — `slm_training.dsl`,
   `slm_training.harness_core`, `slm_training.lineage` — so their dependents can
   vary without editing them.
